# Список отличий библиотек argparse и click

1. Установка
   - argparse: из коробки
   - click: библиотека
2. Передача аргументов
   - argparse: Аргументы добавляются вручную через методы add_argument. Каждый аргумент передается отдельной командой
   - click: Аргументы объявляются декларативно через декораторы @click.option или @click.argument. click.command vs. click.option vs. click.argument
3. Типизация аргументов
   - argparse: по умолчанию str. При указанном аргументе type - сразу во время парсинга (при ошибке выкидывает ошибку)
   - click: тип данных указан в декораторе. Больше типов данных для каста (click.Choice, click.File, click.Path, click.UUID, click.DateTime и пользовательское наследование от click.ParamType) + multi-values options
4. Обязательность аргументов
   - argparse: Всегда обязательны, если явно не указано nargs="?" или default.
   - click: Всегда обязательны, если не задано значение через nargs=-1 или default.
   - required:
     - argparse: только к опциональным аргументам
     - click: как к опциональным, так и к передаваемым аргументам
5. Позиционирование аргументов
    - argparse: Позиционные аргументы всегда следуют строго заданному порядку.
    - click: То же, но поддерживается больше гибкости через параметры, такие как required=False.
6. Вложенные команды
    - argparse: разбор аргументов в одном месте (громоздко). Возможно объединение посредством
    - click: декораторы. Описание аргументов распределено по командам. Удобная группировка
7. Обработка флагов
    - argparse: опция с логическим значением. store_true: True - флаг есть, False - иначе
    - click: Флаг задаётся с использованием параметра is_flag=True. Для флагов значение по умолчанию также False, но его можно изменить, явно указав параметр default
8. Справка:
    - argparse: Стандартная структура с разделами
    - click: Структура справки больше ориентирована на команды, опции и их описание. Вывод справки также более читаем, поскольку информация по каждой опции/аргументу содержится в отдельных строках.
9. Обработка ошибок
    - argparse: Только кастомизация текста ошибок
    - click: Обработка ошибок
10. Тестирование:
    - argparse: Для проверки вывода утилиты используется фикстура capsys, которая даёт доступ к тексту из stdout и stderr.
    - click: в перехвате sys.stdout нет нужды, т.к. есть модуль click.testing с раннером. CliRunner сам перехватывает вывод  и позволяет проверить exit code. Позволяет тестировать click-утилиты без использования pytest и обходиться стандартным модулем unittest.
11. Интеграция терминала:
    - click: гибкая настройка цветов и форматирования
12. Иные особенности:
    - argparse:
    - click:
      - ленивая композиция аргументов (код не выполняется без прямого запуска функции)
      - загрузка переменных среды из коробки (а также добавление новых переменных) (например, click.pass_context)
      - click.echo вместо print и logger
      - click.version_option
      - click.prompt
